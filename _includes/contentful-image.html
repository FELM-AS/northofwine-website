{% comment %} Renders an for a Contentful asset, resized via the Images API (https://www.contentful.com/developers/docs/concepts/images/) rather than serving the original -- these can be several thousand px, which is wasted bandwidth and (with no CSS yet to constrain size) renders comically large. width/height attributes reflect the *resized* dimensions (computed from the original aspect ratio), not the original asset's, so they still correctly reserve layout space and don't lie about what's actually being downloaded. An asset can have a `url` but no `width` (CLAUDE.md: a non-image asset, or one that hasn't finished processing yet, e.g. under CONTENTFUL_PREVIEW) -- resizing needs a real width to compute the proportional height from, so that case falls back to the original, unresized image instead (Plan.md's Error Handling: "Image resizing failures fall back to the original image"), rather than dividing by a blank/zero width.
