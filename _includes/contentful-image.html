{% comment %} Renders an for a Contentful asset, resized via the Images API (https://www.contentful.com/developers/docs/concepts/images/) rather than serving the original -- these can be several thousand px, which is wasted bandwidth and (with no CSS yet to constrain size) renders comically large. width/height attributes reflect the *resized* dimensions (computed from the original aspect ratio), not the original asset's, so they still correctly reserve layout space and don't lie about what's actually being downloaded. Renders nothing if the asset has no url at all -- callers don't need their own "if x.image.url" guard around this include. An asset can have a `url` but no `width` (CLAUDE.md: a non-image asset, or one that hasn't finished processing yet, e.g. under CONTENTFUL_PREVIEW) -- resizing still requests `?w=` (the Images API resizes based on the source file, not on whether contentful.rb happened to expose width/height metadata for it yet), just without width/height attributes, since the resulting aspect ratio can't be computed without an original width to scale from. alt/src are escaped: `description`/`title`/url text ultimately come from Contentful fields editors control, same convention as _includes/button.html's href/text. data-original feeds assets/js/image-fallback.js's two-stage fallback (Plan.md's Error Handling section) -- see that file's own comment for the full behavior. A plain data attribute, not inline `onerror`, so every this include renders is covered by one shared listener instead of repeating the fallback logic per call site. The placeholder path itself isn't repeated here -- it's one site-wide constant, baked directly into image-fallback.js rather than restated on every single image.
