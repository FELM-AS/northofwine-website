{% comment %} Breadcrumb component (Plan.md): / productTypeName / webProductTypeName when both are set on the current product, else / productTypeName. Each segment links to its actual filter page, built by _plugins/contentful_listing_pages.rb -- found here by matching that page's own title (the raw productTypeName/webProductTypeName value the generator titled it with), not by independently recomputing its slug/URL. That way this can never drift out of sync with however the generator actually builds the URL (previously this re-slugified the value itself via Liquid's `slugify: "latin"`, which only stayed correct by coincidentally matching the generator's own Ruby-side Jekyll::Utils.slugify(value, mode: "latin") call). site.utvalg_dir is resolved once by that same plugin via ContentfulJekyll.dir_for, not looked up independently here -- see its class comment for why. Also filtered by `include.product.locale` -- contentful_listing_pages.rb builds one type_page per locale (productTypeName/webProductTypeName aren't Localized Contentful fields, so the same title can appear on more than one locale's filter page), and without this, `first` would always resolve to whichever locale's page happened to be built first (the primary locale's), linking a non-primary-locale product's breadcrumb to the wrong locale's filter page. Same `where: "locale", ` idiom CLAUDE.md's Locales section documents for index.html's homepage grouping (currently inert there -- no collection sets `home: true` yet) -- a no-op here too today, since every page's `locale` is nil (only nb-NO is configured, see _config.yml). `product_filter_pages` precomputes the item_type/locale scoping shared by both the productTypeName and webProductTypeName lookups below, so a future change to that scoping can't be applied to one and missed on the other. Params: product (required) -- a product's page data, e.g. `page` on a product detail page. {% endcomment %} {% assign utvalg_dir = site.utvalg_dir | dir_href %} {% assign product_filter_pages = site.pages | where: "item_type", "product" | where: "locale", include.product.locale %}
